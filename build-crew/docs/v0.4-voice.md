# Build Crew 0.4 voice: findings and fix

Owner report, from his phone: "need the more human voice". The robotic device voice was speaking in Build Crew while
Spell Jump and Wagon West speak with the Google neural voice.

## What was wrong (with evidence)

`tools/voice-check.mjs` plays the game in Chromium against a local server whose `/api/tts/status`, `/prepare` and
`/clip/*` are stubbed the way the service answers (a per-clip synthesis delay, a server-side cache, clip bytes). Only
the shared test hooks are used (`__cloudVoiceBackend` with `load` and `play`, so status and prepare go through the real
fetch path, and `__ttsBackend`, a recorder standing in for `speechSynthesis`). Every line is logged with the engine
that spoke it. Run against the 0.3.0 code (`ASSERT=0`):

| Scenario | Result on 0.3.0 |
|---|---|
| family with a code and a chosen voice, normal network | job goal: cloud |
| same, every API answer 1.8 s slower (a phone on a weak connection) | **job goal: DEVICE (robot)** |
| any scenario | hints, first-use controls, tray tip and machine hints: never spoken; only the goal, the reward, the sandbox line and "Site saved." spoke at all |

The cause is the shape of the pipeline, not one wrong flag:

1. **The 2.5 s race ends in the robot.** `voiceFor` raced the clip request against 2.5 s. When the clip was not there
   in time, `say()` went on to `tts.say()`, which found no clip and spoke the line with the device voice. A phone's
   first request (status, then prepare, then Google making a clip) often takes longer than 2.5 s. This is the failure
   the owner heard.
2. **A line waited behind the background batch.** `prepareVoice` queued `prepareList()` (the 26 Spell Jump spelling
   letters, never spoken here) and then all of `VOICE_LINES` in one request. `cloudVoice.prepare` runs one request per
   voice at a time, so the goal's own `voiceFor` sat behind about 67 texts (two requests of ~2 s each in the stub, the
   first visit of a real family is slower still).
3. **A second fallback inside the shared engine.** Even with the clip prepared, `tts.say()` hands a clip that is not
   fetched and decoded within 4 s (`LOAD_TIMEOUT_MS`) to the device voice for that utterance.
4. **New builders.** A builder with no stored voice only gets the default after an asynchronous status call, and
   `say()` did not wait for it, so the first goal of a new builder in a family with a code could be spoken by the
   device voice.
5. **Strings.** Not the cause for the goal and the reward (both were in `VOICE_LINES` word for word), but the hints,
   machine hints, tray tip and toasts were never spoken at all, and the lines that would have been spoken contained
   `WASD` and unit codes that a voice reads as words.
6. **The test hid it.** The old smoke stage seeded the chosen voice into the family, answered `prepare` instantly and
   asserted `tts.engine === 'cloud'` after saying a line that was not a real game line, so a slow network and the
   real goal could never fail it.

Not the cause: `cloud.active` and the default voice. `applyVoice` selects the default (Ava, `en-US-Neural2-F`, the
same `DEFAULT_CLOUD_VOICE` Spell Jump uses) when the family has a code and none was chosen; the stub run for a family
without a chosen voice (`no-default`) picks it before the first goal.

## What changed

* `src/content.mjs`: the full set of spoken lines is static. `HINT`, `STAMP_HINT`, `TRAY_TIP`, `SPOKEN_TOASTS`,
  `jobIntro`, `jobGoalLine`, `jobDoneLine`, `REWARD_SAY`, `speakable`, `SPOKEN` and `VOICE_LINES` (54 lines, about
  2.7 k characters, made once per voice and shared by every device in the family). The screen copy is unchanged.
* `src/app/voice.js`: rewritten.
  * Lines are prepared at builder select in batches of 8, the next job's lines first, one batch at a time, pausing
    while a line is waiting for its own clip. The Spell Jump spelling letters are no longer requested.
  * `say()` waits up to 9 s for a clip, asking again quietly, and plays it with `cloud.play` (retrying a slow load).
    **A line whose clip cannot be fetched is skipped, never given to the device voice.**
  * The device voice speaks only when the natural voice is not in use at all: no family code, a parent chose a device
    voice, or the service reports it has no key (503) or refuses the family. The first-use extras (hints, toasts, tray
    tip) are natural-voice only, so the robot voice keeps its old, short footprint.
  * `say()` waits for the default voice to be picked before choosing a voice; nothing is spoken before a builder is
    chosen; `{ queue: true }` lines follow the speech in progress instead of cutting it off.
  * The HUD, toasts and tray are not changed: a `MutationObserver` on `#hint`, `#toasts` and `#tray` reads each hint the
    first time a builder meets it (remembered per builder in `buildCrew.<id>.heard`, this device only), the toasts in
    `SPOKEN_TOASTS`, and the tray tip the first time the tray opens. Only prepared lines are ever read.
* `src/app/rounds.js`: the job intro is read when a job starts ("Job three. Foundation grid. Place the three blocks on
  their glowing outlines."), the reward line when the sheet opens ("Job complete. You unlocked the Limestone paint."),
  hints come from `HINT`.
* `src/app/parent.js`: `cloudPrepareFor` prepares Build Crew's lines for the current builder instead of the Spell Jump
  word list. `src/app/title.js`: choosing a builder stops the previous builder's speech.
* `tools/browser-smoke.mjs` (voice stage) and the new `tools/voice-check.mjs` (every spoken moment, each scenario).

## Numbers and unit codes

The service sends plain text to Google; the only SSML it adds is `say-as characters` for a single capital letter
(`cloudLetterText`). The shared `tts.js` has no other say-as convention (a parent's "say as" is a plain replacement),
so lines are written the way they should sound. Rewards drop the unit codes ("the excavator", not "EX-02 excavator").
`speakable` turns `WASD` into "W A S D" and any `AB-01` code into "A B zero one" for text that carries one. Job numbers are
words ("Job three"). No spoken line contains a digit; the progress counter ("3 / 6 placed") is not spoken.

## Spoken moments

| Moment | Line | Rule |
|---|---|---|
| Job starts (any job, once per start) | "Job one. Cargo transfer. Transfer three red loads to the blue delivery zone." | cuts in |
| Read-aloud button | the goal alone | cuts in |
| First time this builder meets a machine | its hint ("W A S D or the left stick drives. This skid steer turns on the spot.") | after the intro |
| First drive, first tool move, first grab, first lift-then-release | "Try I and K, or the right stick, to lift your tool." and the other `HINT` lines | once per builder |
| Reset the blocks | "All set. Resume!" | once per builder |
| Recover machine | "Back on steady ground." | every time |
| Job complete (reward sheet) | "Job complete. You unlocked the Limestone paint." | cuts in |
| Sandbox starts | "Open site. Build, reshape the terrain, and test your own structures." | cuts in |
| Tray opens first time | the tray tip | once per builder |
| Pick a terrain stamp | "Tap a clear patch of ground for your hill." | once per builder per stamp |
| Site saved / cleared, star decal, stripes, material limit, no room for terrain | the toast text | every time |
| Title, builder picker, Parent Zone | nothing | nothing is spoken before a builder is chosen |

## Parent Zone voice picker

Build Crew uses the shared Parent Zone, which has the full "Natural voices (online)" picker of Spell Jump: the six
Google voices (Ava, Daniel, Clara, James, Olivia, Quinn), a Test button each, stored per builder as
`options[<id>].cloudVoice` in the shared family record (`optionsUpdatedAt` set, `writeFamily` marks it for family
sync), so a voice chosen in Spell Jump is the voice here and the reverse. Wagon West does not have its own picker: it
shows a read-only line ("Set in Spell Jump → Parents → Options") and has no default of its own, it reads the same
record. The default is therefore the shared one, `en-US-Neural2-F` (Ava), picked once for a builder in a family with a
code when the service has a key. The `picker` scenario of `voice-check.mjs` opens the zone through the real PIN flow,
checks six voices, the default selected, a pick stored and Build Crew's lines made in the newly picked voice.

## Limits

* A line the service cannot make (offline on the first visit, the family's 20,000-character day used up) is silent;
  its words are on screen. Clips already cached on the device keep playing offline.
* The stub proves the pipeline and the engine choice, not the sound of Google's voice; that needs one listen on a
  phone with the real service.
* Per-device memory of which hints were heard is not synced.

## Running it

```
python3 -m http.server 8094 --directory <repo>
BASE_URL=http://localhost:8094 node build-crew/tools/voice-check.mjs            # all scenarios, asserts
BASE_URL=http://localhost:8094 ASSERT=0 node build-crew/tools/voice-check.mjs slow-network   # trace only
```
